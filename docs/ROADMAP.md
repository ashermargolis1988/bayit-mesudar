# מפת הפיתוח של הבית המסודר

המטרה היא להתקדם במנות קטנות. בכל שלב האפליקציה צריכה להישאר עובדת, ורק אחר כך ממשיכים לשלב הבא.

## שלב 1 — בסיס מקומי עובד ✅

- FastAPI, SQLite וממשק עברי.
- יצירה, הצגה, השלמה ומחיקה של משימות.
- תיעוד API ובדיקות בסיסיות.

## שלב 2 — סדר וארכיטקטורה ✅

- `api/` מקבל בקשות HTTP ומחזיר תשובות.
- `services/` מכיל כללים עסקיים ועיבוד נתונים.
- `repositories/` הוא המקום היחיד שמדבר SQL.
- `schemas.py` מגדיר ומאמת את מבני הנתונים.
- `main.py` נשאר קצר ואחראי רק על הרכבת האפליקציה.

### תרגיל הלמידה הושלם ✅

עריכת משימה נוספה לממשק באמצעות `PATCH /api/tasks/{id}`, כולל כפתורי עריכה וביטול ומילוי הטופס מהמשימה הקיימת.

## שלב 3 — מודל בית ומשתמשים

סדר מומלץ:

1. טבלת `households` לבתים.
2. טבלת `users` עם שם ודוא"ל.
3. טבלת `memberships` המקשרת משתמש לבית ותפקיד.
4. הוספת `household_id` ו-`assignee_id` למשימות.
5. סינון כל שאילתה לפי הבית הנוכחי.
6. בדיקות שמוודאות שמשתמש מבית אחד אינו רואה בית אחר.

אל תוסיף התחברות לפני שהמודל הזה עובד מקומית.

## שלב 4 — התחברות והרשאות

1. הרשמה והתחברות.
2. גיבוב סיסמאות; לעולם לא לשמור סיסמה גולמית.
3. Session או JWT בעוגייה מאובטחת.
4. תפקידי `owner` ו-`member`.
5. הזמנת בן או בת בית בקישור מוגבל בזמן.
6. בדיקות הרשאה לכל endpoint.

## שלב 5 — משימות חוזרות אמיתיות

1. הפרדת תבנית החזרה מהביצוע היומי.
2. שדות תדירות, יום בשבוע ותאריך ביצוע הבא.
3. יצירת מופע חדש למשימה יומית או שבועית.
4. מניעת יצירה כפולה.
5. בדיקות זמן, אזור זמן ושעון קיץ.

## שלב 6 — יתר יכולות המוצר

פתח לפי הערך למשתמש, לא לפי הקלות הטכנית:

1. רשימות קניות ופריטים.
2. אזורים בבית ושיוך משימות לאזור.
3. תזכורות והתראות.
4. קבצים או תמונות למשימות.
5. דשבורד שבועי וסטטיסטיקות.

## שלב 7 — איכות והגנה על המידע

1. החלפת יצירת הטבלאות במיגרציות מסודרות.
2. בדיקות unit לשירותים ובדיקות integration ל-API.
3. לוגים ללא סיסמאות או מידע רגיש.
4. גיבוי ושחזור מסד הנתונים.
5. הגבלת קצב, CORS ומשתני סביבה.
6. בדיקת נגישות, מובייל ו-RTL.

## שלב 8 — פריסה לענן

1. מעבר מ-SQLite ל-PostgreSQL.
2. Docker וקובץ תצורה לסביבת production.
3. סביבת staging נפרדת.
4. CI להרצת בדיקות בכל שינוי.
5. פריסה, HTTPS, ניטור וגיבויים.
6. רק לבסוף: תכנון העברת הנתונים מהאתר החי.

## כלל סיום לכל שלב

שלב נחשב גמור רק כאשר:

- התכונה עובדת דרך הממשק ולא רק דרך `/docs`.
- יש בדיקות לדרך התקינה ולשגיאה מרכזית אחת לפחות.
- אין שגיאות בקונסול או בשרת.
- ה-README עודכן.
- נשמר commit קטן עם שם ברור.
