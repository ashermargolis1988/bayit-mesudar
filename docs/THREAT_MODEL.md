# מודל איומים לסיסמאות ולהתחברות

- **דליפת מסד נתונים.** שומרים גיבוב Argon2id עם salt אקראי לכל סיסמה באמצעות `argon2-cffi>=25.1,<26`. סיסמאות גולמיות וגיבובים אינם נכתבים ללוגים. מגבילים גישה למסד ולגיבויים.
- **ניחוש סיסמאות.** בהרשמה נדרשים 15–128 תווי Unicode. שומרים על הקלט כפי שהוזן, ללא קיצוץ או נרמול. לפני חשיפה מחוץ לסביבה המקומית, מגבילים את קצב ניסיונות הכניסה לפי חשבון ומקור.
- **זיהוי חשבונות.** בכניסה, מחזירים אותה שגיאה עבור סיסמה שגויה וחשבון לא קיים ומבצעים אימות גם מול גיבוב דמה. תשובת דוא״ל כפול בהרשמה עדיין חושפת שהכתובת קיימת.
- **גניבת Session.** השרת מנהל מזהה אקראי עם תפוגה וביטול מיידי. הדפדפן מקבל עוגיית `HttpOnly` ו־`Secure` ב־HTTPS. כך אפשר לבטל את ההתחברות בשרת בעת יציאה.
- **CSRF.** משתמשים ב־`SameSite=Lax` ומוסיפים הגנת CSRF לפעולות משנות מצב לפני חשיפה חיצונית.
- **XSS.** מציגים קלט משתמש כטקסט ומונעים הזרקת HTML. `HttpOnly` מגן מקריאת העוגייה, אך קוד שרץ בדף עדיין יכול לשלוח בקשות בשם המשתמש.

ברירת המחדל היא 64 MiB, שלושה סבבים ומקביליות 4. בפרודקשן אפשר להגדיל זיכרון באמצעות `BAYIT_ARGON2_MEMORY_KIB` (65536–262144) וסבבים באמצעות `BAYIT_ARGON2_TIME_COST` (3–10), לאחר מדידת צריכת משאבים בבקשות מקבילות. הבדיקות משתמשות בברירות המחדל.

אימות משתמש בפרמטרים השמורים בגיבוב. לאחר אימות מוצלח, `password_needs_rehash` מזהה גיבוב ישן או פרמטרים שונים. שכבת הכניסה תוכל לגבב מחדש ולשמור את התוצאה באותו שלב. גיבובי `scrypt` קיימים עדיין ניתנים לאימות.
